# Общий бот: независимые каналы B2B и Kaiten

Доработка подготовлена и проверена локально. На действующий сервер бота НЕ установлена. Владелец согласовал доработку и передаёт этот архив программисту для установки. Сервер бота находится у программиста.

## Состав и совместимость

`common.mjs` — единственная точка запуска и единственный getUpdates poller. `legacy-b2b.mjs`, `protocol.mjs`, `telegram.mjs` сохранены из подготовленного B2B v2; исходная папка B2B не изменялась. `kaiten-protocol.mjs` добавляет отдельный канал с независимой HMAC-подписью.

- `/start` предлагает выбрать B2B или Kaiten. Ссылка `?start=kaiten-test` сразу выбирает тестовый Kaiten.
- Контакт передаётся только выбранному сервису. Группы и чужие контакты не принимаются.
- У каждого сервиса свои origin, ключ, карточки пользователей, статусы, права и сессии.
- Недоступность Kaiten не останавливает обработку B2B. Сообщения каждого пользователя внутри сервиса сохраняют порядок.
- Коды не пишутся в БД и журналы. В БД бота — только идентификаторы доставки и состояния; сообщения регистрации после обработки очищаются.
- Перед запуском проверяются username бота и отсутствие webhook. Код не удаляет webhook.

B2B уже обновлён 27.11.2026 до телефонной регистрации. В этом комплекте по умолчанию используется протокол **2**: `B2B_API_PROTOCOL=2`. Режим 1 оставлен только для явно настроенных старых установок; на текущем B2B его включать нельзя. Kaiten использует собственный протокол **3**. Переключение режима B2B не включает в Kaiten финансовые функции.

## Окружение

Сохранить действующие `TELEGRAM_TOKEN`, `TELEGRAM_USERNAME`, `BRIDGE_KEY`, `B2B_ORIGIN`, `BOT_DATA_DIR`. Не генерировать для них новые значения.

Дополнить окружение бота:

```dotenv
B2B_API_PROTOCOL=2
KAITEN_TEST_ORIGIN=https://test-kaiten.n-smena.business
KAITEN_TEST_BRIDGE_KEY=НОВЫЙ_ОТДЕЛЬНЫЙ_КЛЮЧ_64_HEX
```

Такое же значение нового ключа записывается в `KAITEN_BRIDGE_KEY` только у тестового Kaiten. Оно должно отличаться от B2B `BRIDGE_KEY`; код откажется запускаться при совпадении. Для основной версии впоследствии используются отдельные `KAITEN_ORIGIN`, `KAITEN_BRIDGE_KEY` и сервис `kaiten`, с ещё одним независимым ключом.

## Изменения reverse proxy

В существующем virtual host бота сохранить прежние пути `/bridge/code`, `/bridge/health`, `/bridge/notify`. К существующему matcher добавить:

```text
/bridge/kaiten-test/code
/bridge/kaiten-test/health
/bridge/kaiten-test/notify
```

Они направляются на тот же процесс бота `bot:3103`. Не заменять глобальный Caddyfile сервера. Для основной версии пути `/bridge/kaiten/...` добавляются отдельно при её согласованном подключении.

## Порядок установки после согласования

1. Сохранить код, текущий конфиг и том состояния бота. Согласовать короткое окно с владельцем B2B.
2. Проверить, что подготовлен новый независимый ключ Kaiten и оба адреса настроены правильно.
3. Остановить/пересоздать именно существующий контейнер бота с тем же токеном и томом; не запускать второй контейнер или отдельный poller. Dockerfile запускает `node common.mjs`. Для systemd изменить ExecStart существующего сервиса.
4. Добавить новые proxy-пути, проверить и перечитать конфигурацию reverse proxy.
5. Проверить подписанный `/bridge/kaiten-test/health`: protocol=3, service=kaiten-test, правильный origin. Отдельно проверить прежний B2B-вход в протоколе 2.
6. На тестовом Kaiten подготовить endpoint регистрации и привязать подтверждённый контакт первого руководителя к точному существующему ID. Только после этого включать телефонный вход на всём тестовом сайте. Миграция закрывает старые сессии.
7. Пройти реальный сценарий: контакт → ФИО → заявка → одобрение → код → вход → блокировка. Свой контакт и код отправляет/вводит их владелец.

## Проверка

Node.js 24+, npm-пакеты не требуются:

```sh
node --test test/*.test.mjs
```

15 тестов: маршрутизация, собственный контакт, порядок сообщений, доступность B2B при сбое Kaiten, совместимость B2B протоколов 1/2, отдельная подпись и ключ Kaiten, защита от повторов и однократная доставка кода. Telegram заменён заглушкой; реальные телефоны и токен не использовались.

Полный порядок установки, Compose, Caddy и подготовка .env описаны в ../README.md.
