# Проверка комплекта 27.11.2026

- 61 тест Kaiten: пройден. Бизнес-сценарии, миграция ID и связей, телефонный вход, права, сессии, лимиты, конкурентные отзывы и подписанный канал бота.
- 15 тестов общего бота: пройдены. В том числе B2B protocol 2 по умолчанию, сохранение отдельного legacy-режима 1 только при явном выборе, маршрутизация сервисов, собственный контакт, изоляция ключей, подпись Python/Node, защита от повторов и от второго poller.
- 5 тестов подготовки окружения: пройдены. Старые Telegram-токен/B2B-ключ сохраняются, новый Kaiten-ключ одинаков в двух файлах, повторный запуск его не меняет, конфликт ключей останавливает запись. Отдельному VPS Kaiten не нужен Telegram-токен.
- Синтаксис JavaScript общего бота и интерфейса: проверен Node.js 24.
- Три Compose YAML: прочитаны YAML-парсером; проверены пути build/env/Caddyfile, один bot, отдельный отправитель уведомлений, внешние существующие тома и запрет автоматического создания каталога данных кандидата. Правило замены Caddy mount при merge сверено с официальной документацией Compose.
- Четыре файла Caddy: проверены командой `caddy validate` (Caddy 2.10.2). Проверка не запускала HTTP-сервер.
- Архив: проверка CRC, состава и SHA-256. В `.env` только шаблоны; рабочих секретов, баз, uploads, кэшей и первоначального ключа руководителя нет.

Docker daemon здесь отсутствует. Сборка образов, запуск контейнеров и `docker compose config` этим комплектом локально не выполнялись; команды проверки включены в README для целевого сервера. Unit-тесты используют заглушку Telegram. Реальная доставка, первый контакт владельца, вход B2B после обновления и итоговое переключение Kaiten проверяются при установке программистом.

В рамках подготовки архива действующие серверы, домены и базы не изменялись.
