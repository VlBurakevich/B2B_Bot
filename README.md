# B2B: регистрация и вход только по телефону

Состояние: код подготовлен и проверен локально; НЕ установлен на рабочие серверы.
Рабочий бот bot.n-smena.business отвечает, но пока использует протокол 1. Для регистрации нужен протокол 2 из этого архива.

## Что изменено
- /start → собственный контакт Telegram → ФИО → заявка pending без прав.
- Администратор получает уведомление; заявки и права доступны в разделе «Доступы».
- active / pending / blocked, массив расширяемых прав, аудит изменений, завершение всех сессий.
- Вход только по телефону и шестизначному коду: 10 минут, пауза 60 секунд, пять попыток, ограничения по IP и номеру.
- Хранятся HMAC кодов и SHA-256 токенов сессий. Сессии на 30 дней, cookie HttpOnly; Secure; SameSite=Strict.
- При каждом API-запросе проверяются актуальные статус, права и ограничения amoCRM. Код не выдаёт доступ при отзыве сессий во время проверки amoCRM.
- Старые пароли и ссылки установки пароля больше не принимаются. Поля legacy login/password_hash остаются в БД для совместимости и истории; интерфейс и HTTP-вход их не используют.
- Существующим сотрудникам однократно сохраняются их права на B2B; администраторам — управление доступами. Новые саморегистрации ничего не получают автоматически.
- Состав реестра («свои» / «все»), привязки amoCRM, сделки и комментарии сохранены. Пульс операторов не затрагивается.
- Права reimbursements.create и performer.payouts подготовлены. Самих финансовых модулей в исходном B2B нет: операций с деньгами это обновление не добавляет.

## Два хостинга
service/ — полный обновлённый B2B для pulse-operators.
bot/ + Docker Compose + Caddyfile — для действующего отдельного сервера бота.
Секреты и рабочая база в этот архив НЕ включены. Используются существующие .env на обоих серверах. Токен/BRIDGE_KEY менять не нужно.

## Согласованный порядок установки
1. Сделать резервные копии обоих приложений, базы B2B и тома bot_state. Убедиться, что хотя бы один действующий администратор подтвердил свой телефон в Telegram. Прочие учётки без телефона нужно дополнить через администратора.
2. Подготовить новые файлы на двух серверах заранее. Выбрать короткое окно обновления: новый бот до обновления B2B ещё не сможет обработать регистрацию. Старые веб-сессии будут завершены миграцией, после чего нужен вход через Telegram.
3. На сервере бота заменить bot.mjs, protocol.mjs и Caddyfile. Не заменять существующие .env, bot/.env и volumes. Не запускать второй poller того же бота. В прежнем каталоге Compose:
   docker compose up -d --build bot
   docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
   Caddy должен пропускать /bridge/code, /bridge/notify и /bridge/health.
4. На VPS B2B распаковать архив в служебный каталог. Передать install-b2b.py путь к существующему env с B2B_TELEGRAM_BOT_ORIGIN и B2B_TELEGRAM_BRIDGE_KEY:
   python3 install-b2b.py --env-file /путь/к/действующему-telegram.env
   python3 install-b2b.py --env-file /путь/к/действующему-telegram.env --apply
   Скрипт проверяет точный baseline, подписанный health протокола 2 и администратора с подтверждённым Telegram, останавливает только b2b-control, создаёт резервную копию БД, переключает release, запускает и проверяет API.
5. Проверить реальный вход администратора, регистрацию нового сотрудника, заявку, уведомление, одобрение, вход нового сотрудника и блокировку. Не использовать реальные телефоны для синтетических тестов. Коды вводят только их владельцы.

## API
POST /api/auth/request-code {phone}: одинаковый нейтральный ответ для неизвестного, ожидающего, заблокированного или активного номера; отправка только при active + platform.full_access + подтверждённый Telegram.
POST /api/auth/verify {phone,code}; GET /api/auth/me; POST /api/auth/logout.
GET /api/access; POST /api/access/update {userId,version,status,permissions}; для завершения всех сессий: action="revoke-sessions" и текущая version.
GET /api/access/audit — последние 200 событий, только администратору.
Модифицирующие веб-запросы требуют точного Origin. B2B слушает только loopback, nginx должен перезаписывать X-Real-IP реальным IP клиента и не публиковать 3102 наружу.

## Доставка и данные
- Источник истины о пользователях и правах — SQLite B2B. Бот не кеширует доступы; каждое сообщение проверяет B2B по подписанному HTTPS-каналу с защитой повторов.
- Уведомления об одобрении и новых заявках лежат в outbox и повторяются при сбое. При аварии между отправкой Telegram и подтверждением возможен повтор уведомления (не повтор заявки/прав). Коды в outbox не хранятся.
- Черновик регистрации истекает через 24 часа. Повторная доставка сообщения Telegram не создаёт вторую заявку.
- Карточки blocked не удаляются; телефоны и TG-ID остаются занятыми этим пользователем. Перенос личности требует отдельного административного решения, а не создания дубликата.
- Старые пользователи могут иметь неизвестную историческую дату регистрации: она показана пустой, не выдумывается.

## Откат
Скрипт сохраняет путь к предыдущему release и снимок SQLite. При неуспешном запуске автоматически откатывается код; бизнес-данные не перетираются старой БД. При ручном восстановлении БД остановить сервис и согласовать потерю изменений после снимка. На сервере бота вернуть прежние файлы и пересобрать Compose; том bot_state не удалять. Откат к прежнему коду возвращает прежнюю политику входа по паролю.
